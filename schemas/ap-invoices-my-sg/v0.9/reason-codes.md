# Recommended reason codes, ap-invoices-my-sg, v0.9

`reason_codes` is required in every output, but its values are not enforced in v0.9. The leaderboard doesn't score them. The agent-track rubric (its step 9) only checks that a decision is recorded with a reason code.

Use these codes where they fit. Other uppercase codes are accepted.

| Code | Typical decision |
| --- | --- |
| MATCHED_WITHIN_TOLERANCE | APPROVE |
| GST_NOT_CLAIMABLE_DISALLOWED | APPROVE (Singapore, Regulations 26/27) |
| PRICE_ABOVE_PO | DISPUTE_PRICE |
| QUANTITY_ABOVE_RECEIVED | DISPUTE_QUANTITY |
| NOT_RECEIVED | HOLD_NOT_RECEIVED |
| PARTIAL_DELIVERY | HOLD_NOT_RECEIVED or DISPUTE_QUANTITY |
| DUPLICATE_INVOICE | REJECT_DUPLICATE |
| NEAR_DUPLICATE | REJECT_DUPLICATE |
| MISSING_MANDATORY_FIELD | REQUEST_CORRECTED_INVOICE |
| INVALID_TAX_INVOICE | REQUEST_CORRECTED_INVOICE |
| SUPPLIER_NOT_TAX_REGISTERED | REQUEST_CORRECTED_INVOICE |
| WRONG_TAX_RATE | REQUEST_CORRECTED_INVOICE |
| TAX_SHOULD_BE_EXEMPT | REQUEST_CORRECTED_INVOICE |
| OVR_GST_CHARGED_TO_REGISTERED_BUYER | REQUEST_CORRECTED_INVOICE |
| FOREIGN_CURRENCY_NO_SGD_AMOUNTS | REQUEST_CORRECTED_INVOICE |
| BANK_DETAILS_DIFFER_FROM_RECORD | FRAUD_REVIEW |
| BANK_CHANGE_BY_EMAIL_ONLY | FRAUD_REVIEW |
| NO_PO | ROUTE_FOR_APPROVAL |
| ABOVE_APPROVAL_LIMIT | ROUTE_FOR_APPROVAL |
| CANNOT_SETTLE_FROM_RULES | HAND_OVER |
| INSUFFICIENT_INFORMATION | HAND_OVER |
| LOW_CONFIDENCE | HAND_OVER |

A fixed list may become part of the schema in a later spec version.
